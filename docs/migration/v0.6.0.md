# Migrating to v0.6.0

v0.6.0 is a deliberate pre-1.0 wire-cleanup release. It changes more of the
wire contract than any release before it, on purpose: the project is still
pre-1.0, so a wrong shape costs a regeneration today and a two-year
parallel-publish window once 1.0 ships (see
[Extension model](../06-extension-model.md)). Everything below was taken now
for that reason.

Read this in one pass before upgrading. Each change names what moved, what it
becomes, and why — and every mapping here is also recorded in the relevant
module's `revision` statement, which is the normative source.

## What breaks, in one paragraph

Every optional scalar in the generated Protobuf gained explicit presence, so
Go consumers see pointers where they saw values. Seven classification axes
moved from closed enumerations to identity hierarchies, so the values on the
wire become module-qualified strings. Thirteen generated enum type names lost
a redundant prefix. Two leaves changed scalar type, one was renamed, and a
handful were removed. `buf breaking` reports 51 findings against the previous
release; all 51 are intentional and listed here.

---

## 1. Field presence: scalars became optional

**What changed.** The Protobuf generator never read YANG's `mandatory`
statement, so every scalar leaf was emitted bare. In proto3 a bare scalar has
*implicit presence*: a field set to zero and a field never set serialize to
identical bytes. The model says otherwise in places —
`zone-occupancy-changed/occupancy-count` is documented as "omitted by a sensor
that detects presence without counting — absent, which is not the same as
zero" — and the binding could not carry it. An absent `fault-entry/severity`
likewise decoded as `info`, the lowest tier, because that enum's zero slot is
a real member.

1,676 fields are now `optional`. Fields that stay bare are the ones YANG marks
`mandatory`, led by every notification's `kind`, `sequence` and
`source-device-id`.

**Wire impact.** None for values that were present. A field set to a non-zero
value encodes identically. A field explicitly set to *zero* now serializes
where it previously did not, which is the entire point.

**Go impact — this is the one that will touch your code.** Scalar fields
become pointers:

```go
// before
msg.OccupancyCount = 3
if msg.OccupancyCount == 0 { /* zero, or absent? unanswerable */ }

// after
msg.OccupancyCount = proto.Uint32(3)
if msg.OccupancyCount == nil { /* genuinely absent */ }
```

Read paths through the generated accessors are **unaffected**: `GetX()` keeps
its value-returning signature and still returns the zero value when unset. So
the break is narrower than it first looks — it hits struct literals and direct
field assignment, not reads. The in-tree conformance mocks were updated as a
worked example.

**ce-id impact.** The published test vectors are unchanged. But note two
things if you compute ce-ids: the spec's "clear the producer-assigned leaves"
now means *clear*, not *set to the zero value*, because for a field with
explicit presence those differ; and an event carrying a legitimately zero
value gets a different id than it would have before the upgrade. See
[ce-id spec](../ce-id-spec.md).

## 2. Seven axes became identities

Each of these was a closed `enumeration` on an axis a vendor or a later
standard revision can legitimately extend — the project's own test for an
identity (see the identity-vs-enum section of the
[conventions reference](../reference/yang-reference-conventions.md)). Values on
the wire become module-qualified identity names.

### 2.1 `time-source` — and it was two vocabularies, not one

Signal control modeled this as an identity; the RSU modeled the same question
as a *disjoint* closed enum. Neither could express what the other could. Both
now use one foundation axis.

| From | To |
|---|---|
| `openits-rsu-types:time-source` `gps` | `openits-types:time-source-gnss` |
| `ntp` | `openits-types:time-source-ntp` |
| `local` | `openits-types:time-source-local` |
| `gnss-pps` | `openits-types:time-source-gnss-pps` |
| `ptp` | `openits-types:time-source-ptp` |
| `openits-signal-control-types:time-source-*` | `openits-types:time-source-*`, member for member |

`time-source-local` keeps its normative note that it is not UTC-traceable,
which is what the RSU's SPaT-requires-UTC constraint tests against.

### 2.2 `priority-type` (signal control)

| From | To |
|---|---|
| `none` | *absent leaf* — no request is an absent value, not a value |
| `transit` | `priority-transit` |
| `freight` | `priority-freight` |
| `other` | `priority-other` |
| — | `priority-emergency` is new: a request that biases the sequence without seizing it, as `preempt-emergency-vehicle` does |

### 2.3 Coordination `cycle-state`

Converted on both surfaces at once — the polled readback and the
`coordination-change` notification — because an enum on one and an identity on
the other would be worse than either used consistently.

| From | To |
|---|---|
| `free` | `cycle-free` |
| `in-step` | `cycle-in-step` |
| `transition-add` / `-subtract` / `-dwell` | `cycle-transition-add` / `-subtract` / `-dwell` |
| `local-zero` | `cycle-local-zero` |
| `begin-pickup` | `cycle-begin-pickup` |
| `master-cycle-zero` | `cycle-master-cycle-zero` |

The axis has two altitudes. `cycle-state-persistent` covers the states a
poller can sample; the three instantaneous log markers derive from the root
directly. The polled leaf types to the narrower base, so it *cannot* carry a
marker — an exclusion that used to be a prose caveat. This also retired a
second caveat: the leaf previously had to warn that an absent value was
indistinguishable from `free`, because `free` sat at proto enum value 0. An
identityref has no zero slot.

### 2.4 DMS `technology`

| From | To |

| `unknown` | *absent leaf* |
| `led` / `flip-disk` / `hybrid` / `fiber-optic` / `shuttered` / `lamp` / `drum` | `display-led` / `display-flip-disk` / `display-hybrid` / `display-fiber-optic` / `display-shuttered` / `display-lamp` / `display-drum` |
| — | `display-e-paper` and `display-other` are new |

### 2.5 Perception `zone-function`

| From | To |
|---|---|
| `count` / `speed` / `incident` / `wrong-way` | `zf-count` / `zf-speed` / `zf-incident` / `zf-wrong-way` |
| `presence` | **removed** — region occupancy is the `openits-zone-occupancy` capability's function |

### 2.6 `plan-applied` selection cause: leaf renamed `source` → `trigger`

The enum listed four causes the shared `mode-change-trigger` axis already
named, for the same question asked of a different state change.

| From (`source`) | To (`trigger`) |
|---|---|
| `schedule` / `operator` / `adaptive` / `preemption` | `openits-types:trigger-schedule` / `-operator` / `-adaptive` / `-preemption` |
| `unspecified` | *absent leaf* |

### 2.7 Travel direction — four representations became one

Cardinal direction was a closed enum in reversible-lane, a local identity set
in work-zone, and a free-form `"NB"`/`"SB"` string on
`device-identity-config/linear-reference` that nothing validated.

| From | To |
|---|---|
| `openits-reversible-lane-types:travel-direction` `northbound` … | `openits-types:direction-northbound` … |
| `openits-work-zone-types:wz-direction-*` | `openits-types:direction-*`, member for member |
| `linear-reference/direction` free string `"NB"` | `openits-types:direction-northbound` |

The axis has two altitudes, like cycle-state. `carriageway-direction` admits
exactly one direction of travel; `travel-direction` above it also admits
`direction-both` and `direction-unknown`. Reversible-lane leaves type to the
narrow base, so its former "direction must not be unknown" constraint is now
structural and the `must` was deleted. Work-zone types to the wide base,
because a work zone legitimately affects both carriageways. The
opposing-carriageway constraint on reversible lanes gained the
inner-loop/outer-loop pair it could not previously express.

## 3. DMS activation failure: enum to identity hierarchy

`message-activation-failed/error-type` was a closed seven-member enum
claiming to mirror NTCIP 1203 `dmsMultiSyntaxError`, which has fifteen
members — and it did not represent `dmsActivateMsgError` at all. The three
failures a TMC sees daily (the activation lost to a higher-priority message, a
stale CRC after a library edit, the sign in local mode) all collapsed to
`other` plus prose.

| From | To |
|---|---|
| `syntax` | `activation-error-syntax` |
| `unsupported-tag` | `activation-error-unsupported-tag` |
| `font-not-found` | `activation-error-font-not-defined` |
| `graphic-not-found` | `activation-error-graphic-not-defined` |
| `too-long` | `activation-error-text-too-big` |
| `hardware` | `activation-error-hardware` |
| `other` | `activation-error-other` |

Twenty-five identities now, under two sub-bases that carry the split driving
operator response: `activation-error-content` (the message cannot be rendered
— fix the message) and `activation-error-control` (the sign refused it — check
the sign).

## 4. Scalar retypes, renames and removals

| Change | Detail |
|---|---|
| Detector `delay` | `uint16` whole seconds → `decimal64` tenths, matching NTCIP 1202:2019 §5.3.2.5. A 1.5 s presence-loop delay was previously unrepresentable. **JSON encoding changes from number to string.** |
| Detector `measurement/volume` | `yang:counter64` → `uint32`. It resets each collection period, so counter semantics were wrong. **JSON changes from string to number**, even though `buf` treats the types as compatible. |
| `operation/mmu` container | Renamed `operation/monitor`; old field tombstoned. |
| `mmu-fault-type` identities | `monitor-fault-type`, members `mmu-*` → `monitor-*`. `mmu-none` removed: absence means no fault. Four members added (field-check, port-1, diagnostic, watchdog). |
| `flash-cause` | `flash-exit` removed — leaving flash is a mode transition, reported by `mode-changed`. `flash-fault-monitor` (NTCIP `faultMonitor(5)`) and `flash-other` added. |
| `coordination-change` payload | `new-value` / `previous-value` / `split-number` replaced by typed, unit-bearing leaves: `pattern`, `cycle-length-s`, `offset-s`, `split-s`, `cycle-state`, each with a `previous-` counterpart, plus `phase-number`. |
| `detector-transition` | `lane` and `approach` removed — collector-injected inventory on the highest-rate event. The label now lives once, as `detectors/detector/config/name`. |
| Perception `zones/zone` | `occupancy-count` and `presence` removed; region occupancy is the zone-occupancy capability's. |
| TSAM notifications | `wire-source` removed; both payloads are computed, not decoded. |
| `controller-fault-event/kind` | Narrowed to `controller-fault-event-kind`, so state-tree fault categories are no longer valid kinds for a log transition. |
| Work-zone `temporary-signal` | `default false` removed; absent now means not reported. |

## 5. Generated enum type names lost a redundant prefix

Thirteen enums carried names like `openits.cctv.v1.OpenitsCctvPtzMoveMode`.
That prefix was an artifact: two files in one proto package each declared the
same enum, and the generator resolved the duplicate symbol by renaming
whichever asked second. Each service's enums now live in a generated
per-service `types.proto` in the same proto package, which both `state.proto`
and `events.proto` import — so the declaration has one home and no rename
occurs.

Affected: `PtzMoveMode`, `TourRunState`, `MessageMemoryType`,
`IncidentSeverity`, `LaneFlowState`, `LcsIndication`, `DecisionAuthority`,
`GpsFixStatus`, `SrmRequestStatus`, `FaultSeverity`, `DataQuality`,
`OperationalStatus`, and the former `TravelDirection` (now an identity, see
§2.7). Enum **value** identifiers lose the same prefix, which is JSON-visible:
`OPENITS_CCTV_PTZ_MOVE_MODE_ABSOLUTE` becomes `PTZ_MOVE_MODE_ABSOLUTE`.

Because a proto type is identified by package plus name and not by the file
declaring it, relocating these declarations changed no fully-qualified name,
no wire bytes and no Go symbol. Only the un-prefixing is visible.

## 6. New surface (additive, no action required)

- Work zones: `worker-presence` (presence container), `reduced-speed-limit-kmh`,
  `work-zone-type`, `start-verified` / `end-verified`, and the eight missing
  WZDx `lane-impact` values.
- Incident detection: `incident-collision`, `incident-stopped-vehicle-shoulder`,
  `incident-smoke-fire`, `incident-slow-vehicle`, `incident-animal-in-roadway`,
  `incident-other`; `clear-reason` on `zone-incident-cleared`; `first-observed`
  on `zone-incident-detected`, making detection latency computable;
  `disposition` and `reviewed-by` on `zone-incident-updated`.
- Signal control: ATSPM codes 31, 32/33 and 181; the four
  `vehicleDetectorReportedAlarms` detector-fault identities.

## Upgrade checklist

1. Regenerate or re-pull the Go bindings; fix struct literals and direct field
   assignments where scalars became pointers. Reads through `GetX()` compile
   unchanged.
2. Update producers emitting any value in §2, §3 or §4 to the new vocabulary.
   Consumers matching on identity strings need the same update.
3. If you compute ce-ids, re-read [the spec](../ce-id-spec.md) on clearing
   versus zeroing.
4. If you parse the JSON binding, note the three encoding changes: detector
   `delay` number to string, `volume` string to number, and enum value names
   losing their prefix.
